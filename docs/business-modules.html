ZENROUTER / PRODUCT BLUEPRINT 02

业务模块拆分

四个模块，一条业务闭环。

讨论稿 v0.14 个一级模块二级能力与责任边界2026.10.29

四个一级业务模块统一命名为“组织与权限”“安全与审计”“模型与路由”“额度与成本”，覆盖身份、风险、调用与费用。平台管理与运维作为横向公共支撑。模块方向与名称已确认，本文二级能力和分期仍为建议，不等同于菜单结构、微服务划分或已确认排期。

四个模块是业务责任域；平台管理与运维提供横向公共能力，按需复用。所有“全量记录”均指经过 ZenRouter 的调用覆盖范围；正文可不留存、限定范围／脱敏或完整保存，位置由企业政策限定。

01

组织与权限模块

定位：统一管理人、团队、应用身份以及资源访问范围，为其他模块提供可信的归属和权限依据。

主要用户：平台管理员、团队／项目负责人核心对象：用户、组织、项目、应用、角色、虚拟密钥
IDENTITY & ORGANIZATION / 二级能力
二级模块建议能力范围
U-01用户账号管理创建／邀请、资料、启停、登录会话管理、离职停用；区分控制台操作者与 API 调用主体。身份失效后同步处理相关访问权限。
U-02组织与团队管理企业、部门、团队、成员关系、负责人、成员加入退出与资源归属；支持用户参与多个团队的场景。组织层级及跨团队协作规则待详细设计确定。
U-03项目与应用管理项目、应用、业务用途、环境、负责人、归属组织、标签；作为模型授权、策略作用范围、预算及成本归因的基本单元。
U-04角色与权限管理RBAC、角色绑定、资源作用范围、模型使用权限、配置管理权限和数据可见性；敏感原文查看、导出、策略发布等单独授权。组织隔离覆盖查询、详情、导出及缓存。
U-05应用身份与虚拟密钥服务账号、虚拟密钥签发、有效期、轮换、停用、撤销、归属和可用模型；凭证标识用于审计。应用持有网关密钥，而非上游供应商凭证。
U-06企业身份接入SSO、身份映射与退出／撤权联动；具体身份协议按试点选择。目录同步与自动成员配置作为后续增强建议，不预设首批企业系统。
U-07授权生命周期与委派成员／角色变更、到期回收、负责人移交、停用关联资源和授权变更记录；细粒度委派逐步增强。是否引入申请审批、紧急授权及其流程需业务确认。

边界：本模块负责“身份、归属、权限”，账单模块负责“配额、预算、核算”，网关负责运行时执行。平台管理员不自动拥有全部敏感原文的查看权。对外多租户交付仍待确认，先明确组织／项目隔离口径。

02

安全与审计模块

定位：既保留 AI 交互证据，也识别与处理风险；形成“记录 → 检测 → 处置 → 复核”的闭环。

主要用户：安全／审计人员、获授权的开发者核心对象：请求记录、检测结果、策略版本、风险事件、审计事件
CONTENT SAFETY & AUDIT / 二级能力
二级模块建议能力范围
S-01全量调用记录与检索统一请求列表与详情；包含成功、失败、鉴权未通过、安全拦截、取消、断流和缓存命中。串联身份、路由原因、上游尝试、状态、耗时、费用及内容采集完整性。
S-02AI 交互内容审计请求消息、系统提示词、响应、工具定义与参数、附件引用；关联原始内容与实际发送／返回内容的变换。按可用标识关联会话或业务任务，但这些标识不替代认证。
S-03风险识别与检测器个人信息、凭证泄露、企业敏感信息、提示注入／越狱、业务禁区、工具名称与目标地址风险；支持关键词、正则、分类模型、自定义检测接口。分别记录类别、严重度、置信度和检测器版本。
S-04风险策略管理作用范围、检测阶段、规则条件、优先级／冲突、处置动作、超时及异常行为；支持草稿、校验、试跑、观察模式、灰度、发布、回滚与版本追溯。企业强制规则保持约束力。
S-05在线检测与处置输入、输出、工具参数同步检测；执行放行、脱敏、阻断、告警或限制路由候选。流式支持完整缓冲／分段检测的策略选择，记录已释放范围及中途终止状态。
S-06异步分析与历史重扫完成后的深度分析、新规则历史复查、重复任务控制及分析状态。新判断追加为独立版本，保留原执行结论；仅保存元数据或脱敏内容时，说明历史分析范围。
S-07风险事件与复核命中证据、关联请求、人工确认风险／误报、告警去重；逐步扩展负责人分配、处理记录、状态流转、误报率和处理时长分析。
S-08管理及敏感访问审计检索用户权限、密钥、渠道、路由、安全规则、预算及保留配置的变更，以及原文查看、下载和导出行为；记录操作者、对象、前后摘要、结果与关联标识。
S-09记录策略与数据治理企业选择不留正文、限定范围／脱敏或完整留存；请求与响应可分别设置。独立配置企业内部或获准外部存储、期限与访问权限；策略在写入前生效，临时段、索引、证据、缓存、导出及备份均受约束，不自动转存外部。

边界：“调用记录”是共享业务证据，以本模块为审计和检索入口；“进程运行日志、指标、链路追踪”属于横向运行观测。网关产出请求／尝试事件，各模块产出管理事件，公共记录能力负责可靠写入，不各自维护一套冲突口径。

必须区分：未检测／检测失败／部分检测与检测通过；记录全部调用与保存全部原文；检查工具调用建议与控制工具真实执行。已经发送的内容不会被异步检测撤回，历史重扫也不覆盖原动作。

03

模型与路由模块

定位：统一管理模型供给与调用执行，在权限、地域、安全和预算约束内，选择合适的渠道与模型。

主要用户：平台管理员、应用负责人、开发者核心对象：渠道、端点、模型、业务别名、路由策略、上游尝试、缓存条目
ROUTING GATEWAY / 二级能力
二级模块建议能力范围
R-01上游渠道与端点管理公有供应商、私有模型服务、端点地址、区域、凭证引用、启停、维护状态及配额／容量配置。区分供应商、渠道实例和实际模型映射。
R-02模型目录与能力管理模型清单、版本、业务模型别名、上下文长度、流式、工具调用、结构化输出和支持协议。应用按稳定别名接入，真实能力决定可用候选。
R-03价格目录与版本按渠道／模型维护输入、输出、缓存及可获得的推理等计量项价格、币种、合同价、生效时间与来源；同一价格版本提供给路由估价与账单核算，避免两套配置。
R-04可用性与健康管理连通性和能力校验、成功率、错误类型、429、首 Token 延迟、总耗时、容量状态、健康探测和人工停用；支持故障摘除、熔断与恢复。
R-05统一 API 与模型转发协议适配、参数校验、模型映射、响应／错误标准化、流式透传、背压、客户端取消、超时。明确兼容矩阵，关键参数不静默丢弃。
R-06路由规则与决策按项目、应用、模型别名、请求能力等匹配规则；支持优先级、权重、负载分配、允许候选、成本／延迟偏好、会话稳定性；记录候选排除原因、选择解释与策略版本。
R-07重试、切换与降级区分同模型换渠道与跨模型降级；按错误类别设置重试、Fallback 顺序、总次数和总耗时。跨模型切换保留能力及质量门槛，每次尝试重新满足约束并单独计量。
R-08缓存管理区分网关响应缓存与供应商 Prompt Cache。响应缓存包括适用场景、精确匹配、有效期、失效、命中率及隔离；键需覆盖权限作用域、模型／版本、影响结果的参数、工具和上下文。语义缓存作为后续增强候选。
R-09流量与容量控制执行用户／团队／应用的 RPM、TPM、并发等限制，并管理渠道容量、排队、过载与超时。账单模块定义消费配额，网关组合执行配额和上游容量限制。
R-10智能路由与质量实验按任务、健康、容量、成本、延迟及质量证据动态选模；业务评测集、回放、影子流量、A/B、质量门槛和回滚。业务反馈由应用提供，额外尝试与费用单独归因；影子请求不触发真实工具副作用。

边界：“智能降级”不等于无条件换便宜模型：先满足能力、权限、地域与内容约束，再优化成本和延迟。普通故障切换与质量驱动选模分层建设；流式内容已释放后，不无提示地拼接另一模型响应。

缓存约束：缓存命中仍校验当前权限与适用内容策略；策略更新时按明确规则重检或失效。隔离、脱敏及到期处置覆盖缓存，带副作用工具调用默认排除。网关命中与上游缓存命中的费用口径分开，二者都不默认等于“零总成本”。

04

额度与成本模块

定位：不仅生成账单，还要在调用前控额度、调用中控预算、调用后核算并解释费用。

主要用户：成本管理人员、团队／应用负责人核心对象：成本归属、用量、配额、预算、预占、费用明细、对账记录
BILLING & COST / 二级能力
二级模块建议能力范围
B-01成本归属与核算维度按组织、团队、项目、应用、用户、虚拟密钥、模型和渠道归因；区分调用主体与承担成本的业务单元。用户归因依赖可信身份，不仅依据客户端自报字段。
B-02用量计量与标准化逻辑请求数、上游尝试数、输入／输出／缓存／推理等可获得的用量；区分供应商实际值、网关估算值、待对账状态，保留原始计量口径，避免供应商嵌套用量重复相加。
B-03配额与预算管理用户／团队／项目／应用／密钥的次数、Token、金额额度，周期、重置、额度调整、超限动作和告警阈值。适用的上级与下级约束共同生效，防止通过多个密钥绕开总预算。
B-04成本预估与预测调用前基于候选价格、输入量、输出上限和可用计量信息预估；区分单次请求估价与周期消耗趋势预测。展示估算依据、价格版本、误差／未知项，而非承诺精确扣费。
B-05预算预占与结算计费操作前预占、完成后结算差额、未使用部分释放、异常恢复和重复事件去重。并发占用保持一致；重试、付费检测和影子请求纳入预算，未知用量进入待对账而非直接归零。
B-06费用核算与调整用量关联生效价格版本，形成请求／尝试级费用；分别核算模型调用、检测器和实验开销。失败或取消仍可能产生费用；修正记录保留原因与轨迹，避免重复扣计。
B-07成本账单与对账周期账单、用量／费用明细、汇总、导出、上游账单比对、差异标记和调整记录；按实际可获取的上游粒度对账，不虚构逐请求精确匹配。
B-08成本分析与预警部门／团队／应用成本排行、趋势、预算执行、异常消耗、阈值告警和优化收益分析；进一步统计每个成功业务任务总成本，结合质量评价降本效果。

边界：“价格”是模型资源的基础数据，“账单”是基于用量和价格版本的核算结果；“配额”限制用量，“预算”限制金额，“限流”限制单位时间速率或并发。这里定位为企业内部成本管理，首期不扩展到充值、支付、发票或模型转售商城。

05

平台管理与运维

这些能力服务四个模块，业务规则仍归各自模块；复用基础设施，不把所有规则塞进一个“大策略模块”。

可靠记录与关联标识

接收记录先可靠持久化再执行需留痕的上游调用；统一 request_id、attempt_id、security_event_id 和版本关联，支持补写、去重、积压监控及恢复。强留痕业务在记录异常时停止新调用，并显式暴露缺口。

配置版本与发布流程

共用草稿、校验、差异、观察／灰度、发布、回滚及变更记录；身份、安全、路由和账单模块分别定义规则语义。审批是否强制另行确认。

通知与告警中心

共用通知渠道、订阅、发送、去重及频率控制。风险模块定义风险告警，账单定义预算告警，网关定义故障告警，避免各自重复实现消息通道。

运行观测与总体看板

指标、运行日志、链路追踪、检测与存储健康、配置状态；总览聚合各域指标，不重复核算。分别展示逻辑请求、尝试、技术成功率、检测状态和业务质量。

凭证保管与数据保护

统一保管上游凭证及检测器凭证；身份模块管理应用密钥生命周期，网关管理渠道凭证引用。认证凭证不进入日志；所有数据访问按组织、角色和内容权限约束。

部署、集成与恢复

私有部署、多副本、健康检查、配置有效期、备份与恢复、身份与通知集成；控制侧中断时，旧配置使用受撤权、预算和有效期约束。具体技术栈及容量指标待选型。

06

模块协作与责任边界

采用“归口维护、共同执行、统一证据”的原则，避免多个模块各算一遍、各存一套。

RESPONSIBILITY CONTRACT / 业务责任约定
交叉事项归口维护其他模块如何协作
用户的模型访问权组织与权限维护授权网关实时执行；内容安全按同一作用范围查询证据。
额度与限流账单维护消费额度／预算；网关维护渠道容量网关组合执行请求限制，账单负责一致的预算预占与结算。
模型价格网关维护渠道／模型价格目录账单核算与路由估价引用同一版本；核算规则由账单维护。
调用与管理日志内容安全提供审计入口；各域产出事件公共记录能力可靠接收；账单维护费用账目，网关保留执行证据，运行日志归公共观测。
风险触发换模型内容安全给出风险动作与候选约束网关在交集中选模，账单重新校验相关费用；无匹配候选时明确失败。
缓存与计费网关维护命中、有效性和缓存来源身份／安全策略继续生效，账单按实际调用与检测等消耗核算。
智能路由效果网关管理评测和实验，应用提供业务反馈安全约束实验数据，账单计入影子等额外成本，综合比较质量与收益。

一次 AI 调用，四个模块怎样配合？

  1. 接收请求并留下可靠接收记录 网关 + 公共记录

    生成逻辑请求标识；后续未通过认证、拦截或失败的调用，同样留下可检索状态。

  2. 识别主体、归属与授权 组织与权限 → 网关

    确定真实应用身份、允许模型、组织／项目归属以及本次适用配置版本。

  3. 检查额度与输入风险 账单 + 内容安全

    先检查消费限制，再按策略检测输入；涉及付费检测时先纳入预算预占，其数据地域和权限也受约束。

  4. 查询适用缓存，或选择上游并预占费用 网关 + 账单

    只访问当前权限与策略允许的缓存；未命中时选择获准候选，预占后调用。每次重试、切换或额外付费操作再次核验剩余额度。

  5. 检查并释放输出 内容安全 + 网关

    包括模型输出、工具调用参数及缓存内容；流式按所选模式检测与释放，记录中断和已返回范围。

  6. 结算用量、补齐证据、推进风险处理 账单 + 内容安全

    所有终态都处理已发生费用和未使用预占；未知用量留待对账。追加路由、尝试、费用、安全结果；异步检测生成新的风险判断。

贯穿全链路的关联：request_id 关联一次逻辑请求，attempt_id 关联上游尝试，费用明细与安全事件各自有记录标识，并关联实际 policy_version／价格版本。一次请求可以有多次尝试和多项费用，但不会因此变成多个逻辑请求。

下一轮优先收敛的 5 个业务决策

  • 归属模型：用户、团队、项目、应用之间的关系，以及共享应用的费用承担方。
  • 治理权限：谁能查看原文、调整预算、发布安全／路由规则；哪些变更需要审批。
  • 默认行为：正文留存期限和模式，检测异常、预算不足、记录异常、流式风险各采取什么动作。
  • 计量口径：配额周期、币种、计量单位、预算容差、未知用量及上下级额度约束。
  • 首批模型和场景：协议能力、降级候选与质量门槛、哪些业务适合缓存及试点验收。
