# ZenRouter 开发顺序与任务优先级

2026-11-16 · v0.1 · 建议稿，基于项目骨架现状、[技术架构](technical-architecture.md)第 10.6 与 12 节、[需求基线](product-requirements.md)第 4、12、13 节

## 1. 排序原则

1. **先过架构门槛，再铺开模块。** 架构文档要求 A（薄调用链）、B（多实例额度）、C／C2（留痕与留存策略）先出结果，否则不全面进入模块实现。这三项一旦不通过，会改动契约、表结构和存储方案，越晚发现返工越大。
2. **沿调用链从里往外长。** 先让一次调用真实走通，再给它加身份、额度、留痕、检测；管理界面跟在已存在的运行能力后面，不先做空页面。
3. **集群约束从第一天进测试。** 两副本并发、重启恢复在 D1 阶段就验证，不等到集群部署才发现只支持单机。
4. **P0 闭环优先于 P1 优化。** 质量评测、影子流量、A/B、历史重扫都依赖 P0 的请求记录和策略版本，放在试点之后。
5. **待决策事项按需前置。** 每个阶段只阻塞于它真正需要的输入（见第 4 节），不等所有问题都有答案才开工。

## 2. 阶段总览

| 阶段 | 目标 | 主要产出 | 对应门槛／验收 | 进入下一阶段的条件 |
| --- | --- | --- | --- | --- |
| M0 · 收尾 | 骨架可协作 | 首次提交、CI 在远端跑通、许可证选定 | — | CI 全绿 |
| M1 · 调用链 | 一次调用真实走通 | Gateway↔Adapter 契约、模拟上游、三类入口、凭证认证、请求／尝试记录 | 门槛 A；AC-01、AC-14、AC-16 雏形 | 同协议与已声明的跨协议组合通过契约测试 |
| M2 · 额度账本 | 并发下扣费正确 | 层级额度表、预占／结算／未知用量、两副本并发测试 | 门槛 B；AC-05、AC-06（计费部分） | 并发、重复事件、超时、跨周期用例通过 |
| M3 · 留痕与留存 | 正文按政策可靠记录或不留 | 留存政策解析、JSONL 写入与恢复、违规副本扫描 | 门槛 C／C2；AC-17、AC-18、AC-19 | 杀进程、磁盘满、三种留存模式通过 |
| M4 · P0 模块补全 | 可受控试点的完整功能 | 组织权限与 SSO、模型路由与配置发布、安全检测与策略中心、审计、额度管理、控制台各页 | 门槛 D；AC-02～AC-04、AC-07、AC-08、AC-10～AC-12 | P0 验收场景全部有自动化或手工记录 |
| M5 · 交付与试点 | 能交给企业部署 | 多架构镜像、升级与恢复手册、多主机集群、受控试点压测 | 门槛 E、F；AC-15、AC-20、AC-21 | 声明支持的部署形态逐项验收 |
| M6 · P1 优化运营 | 可验证的优化 | 评测集、影子流量、A/B、动态路由、历史重扫、风险运营闭环、Helm | AC-09、AC-13 | 由试点数据决定优先级 |

M2 与 M3 都只依赖 M1，可以并行；M4 中的四个领域在 M2、M3 完成后也可以分头推进。

## 3. 各阶段任务清单（按优先级排序）

### M0 · 收尾（约 1 天）

| 优先级 | 任务 | 说明 |
| --- | --- | --- |
| P0 | 首次提交并推送 | 让 CI 真正运行一次，修掉远端环境差异 |
| P1 | 选定项目许可证 | 已定为 MIT（2026-11-16），写入 LICENSE 与各包元数据；复用组件仍需保留其版权与 NOTICE |
| P2 | 清理协作约定 | 提交规范、分支策略、PR 模板；可与 M1 同步进行 |

### M1 · 调用链（门槛 A）

| 优先级 | 任务 | 说明 |
| --- | --- | --- |
| P0 | 定义 Gateway↔Adapter 尝试契约 | `POST /v1/attempts`：已选目标、执行约束、request_id／attempt_id；流式事件信封（原生 payload + 生命周期／计量）；写入 `api/` 与 `crates/contracts`，加契约测试 |
| P0 | 模拟上游服务 | 放在 `tests/`，可编排成功、限流、超时、断流、缺用量等行为；后续所有门槛都复用它 |
| P0 | OpenAI Chat 同协议直通 | 非流式与流式；Adapter 关闭 SDK 内部重试；终态与用量回传 |
| P0 | 网关凭证认证 | 摘要存储、状态检查、可信主体；先用迁移种子数据，管理界面放到 M4 |
| P0 | 请求与尝试记录 | PostgreSQL 请求索引与尝试表；成功、失败、鉴权拒绝都有记录（AC-01） |
| P1 | 静态模型目录与选路 | 业务别名 → 端点的最小配置（文件或种子数据），为 M4 的配置发布打底 |
| P1 | Anthropic Messages、OpenAI Responses、Gemini 入口 | 同协议直通，再逐个加入已声明的跨协议组合；不支持的组合明确报错 |
| P1 | 取消与断流 | 客户端断开传到 Adapter 和上游；断流时终态与“部分内容”表达正确 |
| P2 | 真实供应商验证 | 用一个获准供应商核对计量与协议行为；与模拟上游的证据分开记录 |

### M2 · 额度账本（门槛 B，可与 M3 并行）

| 优先级 | 任务 | 说明 |
| --- | --- | --- |
| P0 | 冻结金额契约 | 币种、精度、舍入、周期时区（需决策输入） |
| P0 | 层级额度表与分录 | 企业→部门→成员额度账户、拨款、不可改写分录、余额投影 |
| P0 | 预占与结算用例 | 稳定锁顺序、短事务、幂等结算、释放未用占用；接入 M1 调用链 |
| P0 | 两副本并发测试 | 同一部门并发消耗、重复事件、超时、跨周期 |
| P1 | 未知用量与待对账 | 断流、Adapter 崩溃后的预占保留与人工核对入口 |
| P1 | 价格版本 | 端点价格随版本记录，结算引用版本 |
| P2 | Valkey 共享限流 | RPM／TPM；不可用时的降级策略需单独验证 |

### M3 · 留痕与留存（门槛 C／C2，可与 M2 并行）

| 优先级 | 任务 | 说明 |
| --- | --- | --- |
| P0 | 留存政策模型与解析 | 不留／部分／完整，请求与响应分开；调用前生成获准视图；冲突拒绝 |
| P0 | 不留正文模式的副本扫描 | 日志、错误信息、队列、缓存不含正文（AC-17）；先做这个，因为它约束所有采集点 |
| P0 | JSONL 文件后端 | 单写入者分段、同步确认、尾段恢复、索引引用 |
| P0 | 故障测试 | 杀进程、磁盘满、目录不可写；强留痕调用在无法确认时停止 |
| P1 | 脱敏与限定范围 | 写入前筛选字段与脱敏（AC-19） |
| P1 | 到期清理与 outbox 任务 | Worker 领取、租约、幂等 |
| P2 | Parquet 封存 | 可选；转换中断与回读一致性 |

### M4 · P0 模块补全

M2、M3 通过后四个领域可分头推进；每个领域同时交付后端用例、管理 API 和对应控制台页面。

| 优先级 | 领域 | 主要任务 |
| --- | --- | --- |
| P0 | 组织与权限 | 组织／部门／成员／应用／凭证管理；控制台 OIDC 登录与会话；casbin-rs 角色范围；撤权时效（门槛 D、AC-10） |
| P0 | 模型与路由 | 模型目录与渠道、路由策略（权重、超时、重试、熔断、Fallback、路由解释）；配置草稿→版本快照→发布（AC-02、AC-03） |
| P0 | 安全与审计 | 输入／输出／工具参数同步检测、检测器接口与 Presidio 首个接入、策略中心（观察、试跑、灰度、回滚）、风险事件与基础复核、管理审计（AC-04、AC-07、AC-08、AC-11） |
| P1 | 额度与成本 | 额度分配页、成本归因与导出、供应商对账初版 |
| P1 | 调用记录与原文访问 | 请求详情、原文授权查看与访问审计、生命周期展示（AC-12） |
| P2 | 平台运维页 | 实例、配置版本差异、积压与容量指标；OpenTelemetry 与 Prometheus 接入 |

### M5 · 交付与试点（门槛 E、F）

| 优先级 | 任务 | 说明 |
| --- | --- | --- |
| P0 | 升级、备份与恢复 | 迁移兼容策略、数据库与正文文件联合恢复演练 |
| P0 | 多架构镜像与发布 | amd64／arm64 分别构建测试、镜像摘要、SBOM |
| P1 | 多主机集群 | 负载均衡、共享正文目录、多 Worker、节点故障（AC-15、AC-21） |
| P1 | 受控试点与压力测试 | 固定业务样例，测延迟、成本、资源、滚动下线（门槛 F） |

### M6 · P1 优化运营

试点数据出来后再排序。候选项：业务评测集与质量门槛、影子流量、A/B、动态路由、历史重扫（AC-09）、风险负责人分配与误报分析、Kubernetes／Helm 包装、网关响应缓存。

## 4. 需要提前拿到的决策输入

| 决策 | 最晚需要的阶段 | 不确定时的临时做法 |
| --- | --- | --- |
| 首批供应商、模型与协议组合 | M1 后半（真实供应商验证） | 先用模拟上游；兼容矩阵只列已测组合 |
| 币种、精度、舍入、预算周期 | M2 开工 | 无法替代，需在 M2 前确定 |
| 默认留存模式、允许位置与期限 | M3 开工 | 默认不留正文，文件后端只在显式配置时启用 |
| 企业身份源（OIDC 提供方、目录） | M4 组织与权限 | 开发期用 Keycloak 容器模拟 |
| 风险类别、检测器超时默认动作 | M4 安全与审计 | 先做观察模式，处置动作可配置 |
| 首个试点场景、并发与长流比例 | M5 | 无法替代，决定压测样例 |
| SLO、RPO／RTO | M5 | 无法替代，决定高可用投入 |
| 许可证 | M0 | 已定为 MIT |

## 5. 下一步建议

从 M0 收尾开始，然后进入 M1 的前三项：尝试契约、模拟上游、OpenAI Chat 直通。这三项完成后就有第一条可以端到端测试的调用，后续的认证、记录、额度、留痕都在它上面叠加。

项目许可证已定为 MIT。**币种与金额精度**需在 M2 开工前确定。
