## 1. 决策状态与阅读约定

本文件作为后续产品原型、详细 PRD、架构设计和开发任务拆解的共同输入，不代表技术方案或交付日期已经确定。

### 1.1 已确认方向

1. 项目工作名采用 **ZenRouter**。
2. 建设企业级 AI 路由网关，覆盖统一模型接入、稳定路由、企业治理、观测与成本管理、部署运维能力。
3. 前期讨论中的 P0 和 P1 均属于目标范围，包括质量评测、影子流量、A/B 实验和路由优化。
4. 内容安全与审计是核心能力，而非附加功能。
5. 所有进入网关的调用均应记录，用于追溯和内容风险分析。
6. 风险识别规则、处置策略及相关记录策略需要可配置。
7. 同时提供 OpenAI、Anthropic、Gemini 客户端兼容入口，由下游用户自行选择；支持同协议代理与已声明组合的跨协议转换，OpenAI 是必备入口。

### 1.2 本版提出、尚未最终确定的设计

本文件中的角色划分、页面结构、风险分类、规则执行模型、具体分期和验收方案是为落实上述方向给出的建议。数据保留期限、默认安全动作、部署模式、供应商名单、性能指标和技术栈仍待确定。

初步竞品研究中的商用定价、能力描述和性能宣传不作为本项目验收标准。文末来源用于回溯研究背景，不代表已完成产品实测或选型。

## 2. 产品目标与用户

### 2.1 产品目标

- **统一接入：**应用通过企业统一入口访问获准的公有或私有模型服务。
- **稳定调用：**在明确的权限、安全和预算约束下进行负载分配、故障恢复和模型切换。
- **可控成本：**能按组织、项目、应用和业务任务归因，设置预算并核对实际消耗。
- **安全治理：**识别输入、输出和工具调用内容的风险，按配置进行处置。
- **完整追溯：**还原调用身份、内容、路由、模型尝试、费用、安全判断与管理操作。
- **可验证优化：**通过业务质量评测证明路由优化有效，而非仅比较 Token 单价。

### 2.2 建议角色

| 角色 | 核心任务 |
| --- | --- |
| 企业平台管理员 | 管理供应商、模型目录、组织、全局策略和部署状态 |
| 项目／应用负责人 | 接入应用、管理项目密钥、模型权限、预算和项目策略 |
| 开发者 | 调试请求、查看获授权的调用详情、定位错误和路由问题 |
| 安全／审计人员 | 配置安全策略、调查风险、复核证据、审计变更和数据访问 |
| 成本管理人员 | 分析费用归属、预算执行情况、异常消耗和对账差异 |

角色权限可组合。管理员身份不自动授予所有敏感内容原文的读取权限；具体权限矩阵在详细设计中确定。

### 2.3 核心业务场景

1. 新应用领取企业虚拟密钥，获准使用指定业务模型别名，不直接接触上游凭证。
2. 上游超时或限流后，网关在允许的候选范围内进行受控重试或切换。
3. 平台按部门、项目和应用统计消耗，预算不足时执行配置的限制动作。
4. 请求或响应命中风险规则，平台执行放行、脱敏、拦截、受约束重路由或告警。
5. 审计人员从风险事件追溯原请求、模型响应、路由原因和对应策略版本。
6. 平台用业务评测集验证低成本候选，灰度发布路由策略并跟踪质量变化。

## 3. 产品边界

### 3.1 本期目标范围

- 模型 API 接入与兼容性管理。
- 同一模型的供应商／实例路由，以及不同模型之间的策略选择。
- 身份权限、预算、用量、日志、安全策略、风险分析和审计。
- 路由质量评测、实验、灰度和回滚。
- 企业部署与可运维能力。

### 3.2 暂不纳入首期建设范围

- GPU 调度、模型训练和推理引擎自身优化。
- 完整 Agent 编排平台、工具市场或 RAG 应用平台。
- 对外模型转售、充值支付及结算商城。
- 所有音视频、图片和二进制附件的完整内容检测。

MCP／Agent 治理、多模态深度检测保留后续扩展空间。首期可以检查模型提出的工具调用，但控制工具实际执行，需要执行端或 MCP 网关配合。

“全量请求”指经过 ZenRouter 的请求；未接入或绕过网关的调用不在可见范围内。治理覆盖率需要结合企业接入和网络管理措施评估。

## 5. 调用记录与数据治理

### 5.1 记录口径

所有进入网关的调用都应形成接收记录，包括成功、失败、鉴权拒绝、安全拦截、取消、断流、重试和 Fallback。无法解析或超出接收限制的请求保留可获取的安全元数据、拒绝原因和内容未采集标记，不承诺保留未被完整接收的内容。

调用覆盖范围与正文留存分别配置。企业可禁止保存正文，或仅保存指定应用、方向、字段／事件及脱敏视图；必要的调用元数据、用量与管理审计使用独立的最小字段和期限策略。“不留正文”不表示自动关闭费用账本，也不表示把正文藏进元数据或错误信息。

数据关联建议如下：

- **request_id：**网关生成的一次逻辑调用标识，关联整个处理过程。
- **attempt_id：**一次上游尝试标识；一条请求可以有多次尝试。
- **trace_id／business_task_id：**可选的链路／业务任务关联，不能替代身份认证。
- **security_event_id：**安全判断和风险事件的关联标识。
- **policy_version：**本次调用实际使用的路由和安全策略版本。

区分业务请求数、上游尝试数和实际费用；重试增加消耗，但不增加逻辑业务请求数。客户端再次提交的请求不得仅凭不可信的客户端标识自动合并。

### 5.2 记录内容

| 类别 | 字段范围 |
| --- | --- |
| 身份 | 企业、项目、应用、认证主体、虚拟密钥标识；鉴权失败时记录为未认证 |
| 输入 | 消息、系统提示词、工具定义与参数、附件描述／授权存储引用、协议类型 |
| 输出 | 返回内容、工具调用、结束原因、错误、流式响应完整性 |
| 路由 | 模型别名、候选及排除原因、最终模型／供应商／区域、选择依据、策略版本 |
| 尝试 | 开始／结束时间、重试与切换原因、状态、首 Token 延迟和总耗时 |
| 费用 | 输入／输出／缓存／推理等可获得的用量、价格版本、估算／实际／待对账状态 |
| 安全 | 检测阶段、类别、严重程度、置信度、证据、检测器版本、规则版本、动作和异常 |
| 数据状态 | 是否采集正文、是否脱敏／截断、保留策略、记录状态及分析状态 |

对未经过检测或检测失败的内容，应明确展示“未检测／检测失败／部分检测”，不得显示为“安全”。附件只有链接时，记录链接或摘要不等于检测了附件内容。

### 5.3 存储与访问策略

正文留存是企业可配置能力，不要求所有企业全量保存。元数据、正文、附件、安全证据和管理审计分别配置保留范围、访问、期限和物理位置策略；对象存储既可以部署于企业内部，也可以使用企业批准的外部服务。

- 正文支持不留存、限定范围／脱敏留存或完整留存；请求与响应可分别配置，按部门、应用等指定范围，未明确允许前不持久化正文。
- 存储位置独立于留存范围：支持企业内部存储及企业明确批准的外部目标。内部部署、临时缓冲、缓存、导出与备份均遵守同一边界，故障时不得静默转存到外部。
- 策略在写入前执行。不留正文时，不进入正文 Journal、队列、缓存、SDK／运行日志及风险片段等持久副本；不能先全量写入再立即删除来实现“不存储”。
- 子级仅在企业政策允许的范围内设置，强制留存与禁止留存冲突须明确拒绝发布或调用；原文摘要和向量等派生内容也须获准。
- 上游 API Key、Authorization、Cookie 等认证凭证不写入日志；内容中的疑似凭证按安全策略处理。
- 可追溯原输入、实际发往上游的内容、原模型输出和实际返回客户端的内容之间的变换；是否保存各份原文由记录策略决定。
- 原文查看、检索、下载和导出均实施授权，并记录审计事件。
- 缓存、索引、导出、风险证据和备份应纳入数据生命周期设计，明确到期处置语义。
- 租户或项目隔离应覆盖列表、详情、检索、缓存与导出。
- 仅保存脱敏内容或元数据时，历史重扫能力相应受限，界面应说明可分析范围。
- 实时风险检测可以在受控内存中执行，不自动要求保存原文；模型推理、外部检测器的数据外发政策与日志存储政策分别执行。

### 5.4 完整性与异常

对企业政策要求可靠保存的接收元数据和选中内容，先可靠持久化再执行受该要求约束的上游调用；结果、安全事件和费用按各自允许范围补齐。禁止留存的正文不能为了可靠性先落盘。不留正文的调用不依赖正文归档服务；具体持久化机制由技术方案确定。

记录模块需要具备去重、补写、积压监控和异常恢复能力。进程中断时，尚未完成的请求显示为未完成或状态未知，不能自动标记成功。持久化缓冲也必须有容量与告警。

正文状态分别显示按策略未留存、部分留存、已到期删除、等待归档、记录失败；按策略未存不能误报为数据丢失。仅保存最终风险命中／错误事件的条件策略，需说明选择结果出现前的缓冲及不可恢复边界，不宣称所有输入都已可靠留存。

无法可靠记录时必须执行显式策略。对强留痕业务，建议拒绝新调用。若允许应急放行，应作为例外政策单独确认、报警并暴露留痕缺口，不能继续宣称这些请求已完整记录。

## 6. 内容安全

### 6.1 检测对象与初始风险类别

检测对象包括输入文本、系统提示词、模型输出、工具调用参数，以及明确支持的附件内容。

建议首批覆盖：

1. 个人信息、密钥凭证、企业自定义敏感数据等泄露风险。
2. 提示注入、越狱、诱导泄露系统提示词等攻击行为。
3. 企业定义的违规内容、业务禁区和领域限制。
4. 工具名称、参数、目标地址等违反调用政策的行为。

类别、严重程度、置信度分别建模。检测结果是规则或检测器的判断，不等同于对业务合法性或事实正确性的最终结论。

### 6.2 四条检测链路

| 链路 | 目标 | 可能动作 |
| --- | --- | --- |
| 输入同步检测 | 内容发送到模型前完成必要检查 | 放行、脱敏、阻断、转至获准候选 |
| 输出同步检测 | 返回客户端前检查输出 | 放行、脱敏、替换响应、阻断后续输出 |
| 异步分析 | 对调用内容进行深入检测 | 标记、告警、生成事件、人工复核 |
| 历史重扫 | 用新规则或检测器复查保留数据 | 新增分析结果、评估规则效果、发现遗漏风险 |

异步分析不能撤回已经发送的内容。历史重扫不覆盖原始执行记录：保存当时的判断，同时增加新版本分析结果。

检测器自身可能调用外部服务，应受数据地域、访问权限、日志和成本策略约束，避免安全检查成为额外的数据外发通道。

### 6.3 流式响应

- 支持按业务选择“缓冲完整响应后检测”或“分段检测后释放”等模式。
- 完整缓冲会改变首段可见时间和实时体验，需在策略配置中说明。
- 分段检测需要处理跨段上下文；已释放内容无法撤回，命中后只能阻止后续输出并记录已释放范围。
- 字节／片段事件记录与最终内容聚合是不同存储粒度，是否长期保存全部原始流事件待确定。
- 中断、超时、取消和缺失尾部用量必须显示不完整状态。

## 7. 策略中心

### 7.1 规则结构

| 维度 | 配置内容 |
| --- | --- |
| 作用范围 | 企业、部门、项目、应用、认证主体、模型、数据类别 |
| 检测位置 | 输入、输出、工具参数、异步记录、历史记录 |
| 检测方法 | 关键词、正则、敏感数据识别、分类模型、自定义检测接口 |
| 命中条件 | 类别、严重程度、置信度、组合条件 |
| 处置动作 | 记录、告警、脱敏、阻断、受约束重路由 |
| 执行模式 | 观察、正式执行、灰度 |
| 异常策略 | 检测超时、服务不可用、结果不完整时的行为 |
| 发布信息 | 版本、变更原因、操作者、生效范围、发布时间 |

### 7.2 必须保持的约束

1. 企业强制策略不可被项目策略放宽。各层规则冲突的具体优先级需要在详细设计中定义。
2. 身份、授权和地域等强约束先确定可用候选，再进行成本、质量或延迟优化。
3. Fallback、重试、重路由、影子流量和缓存命中均不得绕过适用安全规则。
4. 没有符合条件的候选时明确失败，不自动跨越安全边界。
5. 风险重路由设置次数上限，防止策略循环；目标端点仍需满足完整能力与权限要求。
6. 观察模式只记录拟执行动作，不按该规则实际拦截；其他已生效强制策略继续执行。
7. 配置版本需可回溯，回滚不抹除历史版本或审计信息。

### 7.3 示例策略（仅示意）

对“研发助手”输入检查凭证及内部敏感信息。发现凭证则阻断；识别为内部敏感内容时，只允许发送到企业批准的私有模型端点。没有获准候选则返回明确错误。记录命中证据、实际动作及策略版本；正文是否加密保存、保留多久由该项目记录策略控制。

### 7.4 策略发布流程

编辑草稿 → 配置校验 → 历史样本试跑 → 观察命中与误报 → 灰度发布 → 正式生效 → 持续评估或回滚。

审批是否强制、哪些角色可以紧急发布和回滚，留待组织权限设计确定。

## 8. 路由、预算与质量优化

### 8.1 路由行为

下游协议与上游协议分别建模。同一 Anthropic 上游需同时支持 OpenAI Chat 客户端的转换接入与 Anthropic Messages 客户端的同协议接入，按调用方选用的端点返回对应格式。OpenAI Responses 是独立兼容项；Gemini 同样提供原生入口。可选协议组合受模型能力约束，不承诺任意互转；全部入口共用权限、额度、安全和审计要求。

- 区分同一模型的供应商／实例切换和不同模型之间的切换。
- 为候选记录协议、工具调用、结构化输出、上下文长度、数据地域等能力条件。
- 支持业务模型别名，使业务方不必因日常策略调整修改应用。
- 路由结果应能解释：哪些规则命中、为何排除候选、为何最终选中。
- 超时、429、鉴权错误、内容拦截等错误分别定义是否可重试，限制总次数和总耗时。
- 流式内容已对客户端释放后，不得无提示地重新生成并拼接另一份响应。
- 多轮会话和 Agent 调用需要会话／任务路由稳定性设计，明确何时允许换模型。
- 客户端取消后应尽力中止上游；实际已产生的用量仍需要记录和结算。

### 8.2 预算和费用

预算需要预占、完成结算、异常释放或对账，而非仅事后告警。并发预占必须有一致性约束，准确的估算上界、容差和欠账处置在技术设计中确定。

区分供应商返回的实际用量、网关估算值和待对账数据。定价版本与合同价要可追溯；输入、输出、缓存、推理用量、重试、检测器调用和影子流量均需要明确计费归属。安全检测和路由优化自身的费用计入总成本分析。

### 8.3 P1 质量闭环

建立有版本的业务评测集与指标，再比较固定模型、规则路由和智能路由的质量与成本。支持离线回放、影子流量和 A/B 实验；生产数据回放和影子请求仍受相同的权限、地域及内容安全约束。

影子请求不影响主响应，但产生独立尝试和费用；不得自动执行具有真实副作用的工具操作。实验分组粒度需考虑会话一致性。

业务成功率、任务质量、每个成功任务总成本、延迟和故障率共同决定优化效果。没有业务反馈或评测证据时，不宣称质量不变或已经实现某个降本比例。

## 9. 审计与风险运营

### 9.1 调用审计

追溯认证主体、输入输出、模型尝试、路由、策略判断、费用及最终结果。调用详情关联风险事件、策略版本与内容变换，不将敏感原文直接暴露在所有列表或告警中。

### 9.2 管理审计

记录组织权限、密钥、模型端点、路由规则、安全规则、预算、记录保留策略的变更，以及原文查看、导出和重要运维动作。

审计事件至少包含操作者、时间、对象、动作、结果、变更前后摘要和关联标识。业务接口不得允许无痕改写历史审计事件；防篡改、导出验证和保留机制由技术方案细化。

### 9.3 风险事件工作台

- 按项目、应用、主体、时间、风险类别、严重程度、规则和处置状态检索。
- 查看命中片段、检测依据、对应请求和模型尝试。
- 人工标记确认风险、误报、需进一步调查；保留原检测结论和复核过程。
- 支持负责人、处理记录和状态流转，建议状态为待复核、处理中、已处置、已关闭。
- 同一请求的多次检测应关联展示；告警需要去重与频率控制。
- 风险趋势、规则命中率、人工复核误报率、检测失败率和处理时长分别统计。

## 11. 概念架构与非功能要求

概念上分为三部分，具体实现尚未选型：

- **数据面：**认证、强约束检查、同步安全检测、路由、模型调用与响应处理。
- **控制面：**组织、模型目录、预算、安全与路由策略的配置及版本发布。
- **记录与分析：**可靠接收记录、补写、异步风险分析、索引、成本分析与审计。

控制面短暂不可用时，数据面可根据明确的配置有效期策略使用最后一个已验证版本；撤权、撤销密钥、预算一致性和策略过期不能因此失去约束。

非功能要求应覆盖：

1. 多网关实例通过统一入口承接流量，支持横向扩容、故障摘除和滚动升级；入口及共享依赖避免单点。多副本下权限、预算、限流和配置的一致性，以及故障恢复需验证。
2. 长连接、流式背压、取消、超时与大请求边界。计划下线先摘除新流量并等待存量连接结束；实例故障导致的中断需如实标记，不承诺已输出流无缝迁移。
3. 日志和分析积压可见，故障不会被误报为安全或成功。
4. 内容、凭证、缓存和审计的隔离及加密。
5. 策略及依赖服务升级、回滚和备份恢复可操作。
6. 安全检测开销与纯代理开销分开衡量，避免混淆性能指标。

可用性、吞吐、并发、请求大小、P95/P99 延迟、记录恢复时间、数据保留规模等数值均待真实流量和业务要求确定。

## 12. 验收场景基线

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 成功、失败、鉴权拒绝和安全拦截分别发起调用 | 均可检索接收记录；记录主体可信度、最终状态和缺失字段原因 |
| AC-02 | 同一请求触发重试和 Fallback | 一个逻辑请求关联多个尝试，路由原因及所有实际费用可追溯 |
| AC-03 | 敏感数据仅允许发往指定端点，该端点不可用 | 不切换至未经允许的候选，返回可解释错误 |
| AC-04 | 流式响应中途命中风险或断流 | 已释放内容不被伪装成可撤回，后续处置明确，记录完整性准确 |
| AC-05 | 并发调用接近预算上限 | 预占／结算行为符合确定的预算容差，无静默失控或重复扣费 |
| AC-06 | 记录服务故障、进程重启或事件重复投递 | 已可靠接收的记录可恢复或标记未完成；重复事件不重复计费；强留痕策略生效 |
| AC-07 | 安全检测器超时或失败 | 执行配置的异常动作，显示失败状态，不显示为检测通过 |
| AC-08 | 同一条规则从观察模式切换为执行模式，再回滚 | 观察期仅记录拟执行动作；生效和回滚范围正确，版本历史完整 |
| AC-09 | 新规则重扫历史内容 | 新增分析版本，不改写历史动作；未保留内容明确标记不可分析 |
| AC-10 | 普通项目成员读取其他项目日志或导出敏感原文 | 未授权访问被拒绝，敏感访问与导出事件可审计 |
| AC-11 | 修改安全规则、角色、预算及保留策略 | 操作者、对象、变更摘要、结果和版本均可追溯 |
| AC-12 | 数据到期及风险证据存在不同保留策略 | 按已确定的生命周期执行，并说明索引、证据、备份的处置状态 |
| AC-13 | 发布低成本路由、影子实验或 A/B | 满足安全与能力约束，独立计量额外成本，质量与延迟可与基线比较 |
| AC-14 | 私有部署与客户端功能验证 | 按约定能力矩阵通过真实流式、工具调用及结构化输出用例，不静默丢弃关键参数 |
| AC-15 | 多实例入口分流、扩缩容、实例故障和滚动升级 | 新请求被分配至就绪实例；计划下线按约定排空；全局额度与限流不随实例数放大，配置生效和中断记录可追踪 |
| AC-16 | 下游自行选择 OpenAI 或 Anthropic 接口调用同一 Anthropic 上游，并验证 Gemini 原生入口 | 请求、响应、流式及错误符合所选接口；治理规则持续生效；OpenAI Chat／Responses 分项验证；不支持的组合明确报错，不静默丢失关键字段 |
| AC-17 | 企业禁止正文留存，触发成功、错误、风险、重试及取消 | Journal、缓存、队列、运行日志、风险证据和备份无正文及未经允许的派生副本；仍有获准计量，页面显示按策略未留存 |
| AC-18 | 企业只允许内网存储，目标不可用或达到容量上限 | 正文、临时段、备份与导出均不转存外部；仅受影响的留存分支按故障政策执行 |
| AC-19 | 仅对指定应用保存脱敏响应，其他正文禁止留存 | 写入前完成范围筛选与脱敏；请求原文及未选中字段不先写后删，子级不能扩大企业允许范围 |
| AC-20 | 分别安装本地开发、Docker 单应用容器、Compose 与集群 | 声明支持的形态分别通过初始化、代表性协议调用、权限／额度／留存一致性、重启和升级检查；外部依赖与限制明确，未验收形态不能标为正式支持 |
| AC-21 | 集群启用文件正文留存并发生节点切换 | 其他获准节点能够定位和读取已确认文件，任务重试不产生重复有效归档或误删；缺少共享目录明确拒绝不满足条件的留存模式，不自动上传到外部 |

以上是验收设计输入，不代表测试已经执行或通过。

## 14. 后续工作建议

1. 选择一个真实试点场景，补齐首批接入、数据规模和安全策略样例。
2. 设计请求详情、安全策略编辑和风险复核三个关键流程的原型。
3. 将本文件拆成详细 PRD：字段、状态、权限矩阵、错误行为、策略优先级及可测量指标。
4. 对候选底座验证协议保真、流式行为、故障处理、预算准确性、全量记录和扩展机制，再决定技术选型。
5. 用试点结果制定 P0/P1 里程碑，不把前期讨论中的探索时间直接当成交付承诺。
