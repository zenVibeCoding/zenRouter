# ZenRouter 功能模块与初版原型

版本：v0.1 · 基于已对齐的产品范围和四模块技术调研。

本版把业务责任转成控制台页面，帮助讨论模块划分、信息层级和核心操作。不代表正式 PRD、生产系统或已经通过验证的技术方案。

2026-10-30 留存方向更新：企业可选择不留正文、限定范围／脱敏或完整留存，并独立选择仅内网或获准外部存储。“审计与留存”页面补充这一能力说明；现有 30／180／365 天及完整正文样例仅代表一种配置，尚未实现政策编辑、后端执行或不同模式切换。

## 2. 业务模块划分

| 业务模块 | 负责解决的问题 | 主要管理对象 | 主要使用角色 | 与其他模块的边界 |
| --- | --- | --- | --- | --- |
| 组织与权限 | 谁在使用，在哪些范围内可以调用和管理 | 部门、员工、项目与应用、角色、身份源、虚拟密钥 | 平台管理员、部门主管、应用负责人 | 管理身份与授权；不直接核算费用和扣减额度 |
| 模型与路由 | 可以调用哪些模型，如何稳定调用 | 供应商渠道、真实模型、业务别名、协议、路由、缓存 | 平台管理员、应用负责人、开发者 | 在权限、安全、能力和额度约束内选择并执行 |
| 安全与审计 | 交互了什么，风险如何判断和复核 | 请求、响应、尝试链、检测规则、风险事件、审计证据 | 安全审计人员、获授权开发者 | 检测与复核分别留存；原文读取不随管理员身份自动授予 |
| 额度与成本 | 谁能分配，还能用多少，费用如何核对 | 周期额度、分配、预占、消费、计量、供应商账单 | 额度管理员、部门主管、成本人员 | 分配不是消费；供应商消耗不是供应商余额 |

“工作总览”和“功能地图”是跨模块入口；“平台运维”是横向公共能力。质量与实验归属于模型与路由，保留 P1 入口。导航页面不等同于部署服务，也不新增第五个业务模块。

## 4. 三条优先评审的业务路径

### A. 应用接入与调用

组织与成员 → 应用与密钥 → 接入应用 → 选择归属部门、允许模型和示例协议 → 查看网关接入说明 → 调用记录。

应用领取网关虚拟密钥，供应商凭证保持在平台内。OpenAI、Anthropic、Gemini 入口并存，实际协议与模型组合需要验证后公布。新建演示应用不会生成真实调用记录或签发真实凭证。

### B. 企业与部门逐级分配额度

额度分配 → 企业范围查看已分配部门 → 进入研发部 → 给林知远追加 500 美元 → 观察未下发额度由 2,000 变为 1,500，员工额度由 5,200 变为 5,700。

部门的 10,000 美元总额度、企业的 30,000 美元总额度和已有消费均不因下发而增加。超出未下发范围的分配会在原型中被拒绝。新建部门初始额度为零，可由企业范围拨款。

“尚未下发”表示可向下级委派的额度；“剩余可调用”表示额度上限减已消耗和已预占，两者分别展示。回收、转移、周期重置与申请审批后续细化。

### C. 调用追溯与风险复核

调用记录 → 打开 req-001 → 查看两次尝试与各自费用 → 查看内容证据／费用；或打开 req-002 → 关联风险事件 → 追加复核结论 → 查看审计记录。

一次逻辑调用可以包含多个上游尝试。鉴权拒绝与输入安全拦截不调用上游；流式中断保留部分内容与未知用量，不显示为完整成功或零消费。人工复核“误报”不会抹除当时已经执行的拦截。

原文查看提供“申请”入口作为交互讨论方案；正式采用申请、预授权还是其他方式尚未确定。演示提交申请不会自动授予权限，也不会展示真实原文。

## 5. 示例数据与交互约束

所有企业、人物、模型别名、渠道、金额、性能指标和事件均为产品演示数据，没有真实业务含义。示例快照使用 2026.10.29，额度周期使用 10.26—11.01；这些不是最终业务时区或重置规则。

原型使用当前浏览器标签的会话存储保存操作。没有服务端、登录会话、实际授权、计费或网络模型调用。浏览器禁用会话存储时，数据只保存在当前页面内存；“重置本地演示”恢复初始样例。示例密钥明确无效，配置表单不收集真实凭证。

总览、趋势与用量多数为固定快照。分配额度会更新对应金额和分配记录，复核会更新事件及审计，其他新增操作不会自动伪造实时调用量、费用或检测效果。

## 6. 目前需要评审什么

| 评审主题 | 主要判断 |
| --- | --- |
| 模块和入口 | 四个业务域是否清晰，日常工作能否迅速找到入口 |
| 管理范围 | 公司、部门、员工、项目、应用的关系是否符合实际企业使用 |
| 核心对象 | 是否能围绕一条调用定位身份、模型、尝试、内容、费用和风险 |
| 额度口径 | 是否能区分拨款、可委派、预占、消费、供应商余额和最终账单 |
| 操作权限 | 管理、发布、分配、原文查看与导出是否需要独立授权 |
| 分期 | 首个试点闭环与后续实验、复杂分析的边界是否合理 |

评审后再补充详细字段、状态流转、默认策略、权限矩阵、异常页和实际验收标准。当前原型不承担已部署能力证明。

## 7. 原型验证与维护

源文件为 [prototype.html](prototype.html)、[prototype.css](prototype.css)、[prototype.js](prototype.js)。静态图由浏览器直接截图，交互源文件是后续修改的主版本。

[浏览器检查脚本](../scripts/check-prototype.cjs)覆盖 18 个页面的桌面／窄屏加载、页面宽度、请求筛选、调用详情、原文申请、额度分配与超额拒绝、草稿与发布、风险复核、主备切换限制、示例应用／部门创建、实例排空与会话保留。执行需要 Node.js、Playwright 和 Chromium；可通过 PLAYWRIGHT_MODULE 指定已有模块路径。

这些检查验证的是原型交互和展示，不验证真正的身份安全、账本一致性、模型协议、故障切换或生产性能。
